# Журнал зарядки EV — что сделано, как и почему

## Зачем это вообще понадобилось

История зарядок в приложении зарядника ("X Smart EVSE") — единственный источник данных о кВтч, стоимости и длительности сессий. Полагаться на то, что приложение никогда не сбросит и не забудет эту историю, нельзя. Нужен был независимый журнал.

## v1 — черновик внутри Claude

Первая версия была собрана как артефакт Claude (`window.storage`, публикация по ссылке). На этом этапе выяснились два ограничения платформы:

- Хранилище артефакта работает только у **опубликованной** версии — черновик/превью в чате данные не сохраняет.
- Каждая новая публикация после правки кода создаёт **новую ссылку с пустым хранилищем** — обновить существующую "на месте" нельзя. Из-за этого был добавлен экспорт/импорт CSV как страховка перед каждой правкой.

## v2 — переезд на git + собственное облако

Решили не оставаться в этой модели и вынесли файл (`index.html`) в собственный git-репозиторий. Хранение переделали с `window.storage` на **JSONBin.io**:

- Один общий "bin" (хранилище) зашит в файл (`BUILT_IN_BIN_ID`), у каждого устройства — свой ввод **Master Key** (один раз при первой настройке, хранится в `localStorage` этого браузера).
- Все устройства с одним и тем же ключом видят один и тот же журнал — так синхронизация работает и на телефоне, и на компьютере, и уже подтверждена рабочей в оба конца.
- Дополнительно ведётся локальный кэш (`localStorage`) — если нет связи с облаком, журнал показывает последние загруженные данные и продолжает работать.
- Индикатор синхронизации (точка рядом с датой) показывает статус: синхронизировано / идёт сохранение / нет связи — локально / нет ключа.

Почему так: постоянная ссылка (не меняется при правках кода), не зависит от плана подписки Claude, и данные общие на несколько устройств "из коробки" — ровно то, чего не хватало в v1.

## Функциональность на сегодня

- Ввод сессии: дата, энергия (кВтч), цена за кВтч (подставляется последняя введённая), время начала/окончания, пробег (одометр, км — общий счётчик машины, не суточный трип), заметка.
- Автоматический расчёт стоимости и средней мощности сессии.
- Редактирование существующей записи (не только добавление/удаление).
- Удаление — через подтверждение ("Удалить? Да / Нет"), не мгновенно.
- Экспорт/импорт CSV — независимый бэкап; импорт пропускает уже существующие записи (по дате+кВтч+длительности+заметке), повторный импорт не дублирует.
- Сводка: суммарные кВтч (с анимацией), число сессий, итоговая стоимость, средние кВтч и мощность по сессиям.
- **График по месяцам** (новое): кВтч (столбики) и стоимость ₪ (линия с точками) по каждому месяцу. Собственный SVG на чистом JS, без внешних библиотек и интернета для отрисовки — не зависит от CDN.
- Оформление отсылает к реальному электрощитку — пронумерованные "слоты" записей как позиции автоматов, зелёный индикатор как LED на автоматах, медно-янтарный акцент в цвет медной шины щитка.

## Фикс: формат времени

Поля времени начала/окончания сессии первоначально были нативными `<input type="time">` — а такой инпут показывает 12- или 24-часовой формат в зависимости от локали браузера/ОС, а не от самого HTML. Универсального атрибута "покажи 24 часа" не существует.

Заменили на пару простых числовых полей **ЧЧ / ММ** для начала и для окончания — всегда 24-часовой ввод, без сюрпризов на любом устройстве. Внутри данные по-прежнему хранятся строкой "ЧЧ:ММ" — остальная логика (расчёт длительности, CSV) не менялась.

## Решили НЕ делать: автоматическое подтягивание тарифа IEC

Возник вопрос — можно ли автоматически вытягивать актуальный тариф с сайта IEC вместо ручного ввода. Проверили и отказались от идеи:

- Страница IEC рисует тариф через JavaScript в браузере — сырой HTML-запрос (что прямой, что из кода журнала) не содержит числа вообще.
- Даже если бы это не мешало — сработал бы **CORS**: браузер блокирует такие кросс-доменные запросы к чужому сайту независимо от того, вызван запрос автоматически или по кнопке.
- Чтобы реально прочитать цифру, нужен headless-браузер (Selenium/Playwright) — то есть отдельный сервис, который надо где-то регулярно гонять и чинить при любом изменении вёрстки сайта.
- К тому же "тариф" — не одно число: единый тариф, тариф теу"ز (по часам/сезонам), плюс возможные скидки у частного поставщика.

Тариф меняется пару раз в год по решению регулятора — не тот случай, где нужна инфраструктура. Решили оставить как есть: поле цены запоминает последнее введённое значение, при изменении тарифа достаточно один раз вписать новое число. Классический случай **YAGNI** (You Aren't Gonna Need It) — не строить то, что не понадобится.

## Текущий статус

- Журнал живёт в git, синхронизация между устройствами через JSONBin подтверждена рабочей.
- Экспорт/импорт CSV работают и остаются штатным способом бэкапа.
- Пробег per session пока не ведётся регулярно (неудобно снимать на ходу) — но поле уже готово, график расхода на 100 км появится, как только накопятся пары показаний одометра.
- Следующие возможные графики (обсуждались, не сделаны): расход кВтч/100км, средняя мощность сессий по времени, привычки по дням/часам зарядки.
